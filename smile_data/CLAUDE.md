## fmriprep — session-specific preprocessing notes

Each session has its own T1w. When running fmriprep on only new sessions (via `--session-label`), each session's functional data is registered to that session's own T1w. Compatibility across sessions depends on the output space:

- **Surface spaces (fsnative, fsaverage5, fsLR 32k)** — ✅ compatible. FreeSurfer is reused from the first run (output lives in `derivatives/sourcedata/freesurfer/sub-XXX/`); both sessions' bold data is projected to the same surface reconstruction via bbregister.
- **MNI152NLin2009cAsym** — ✅ near-compatible. Each session gets its own T1w→MNI warp; differences between sessions are typically sub-mm for the same subject.
- **T1w (native volume)** — ❌ not comparable across sessions. ses-1 functional is in ses-1 T1w space, ses-2 in ses-2 T1w space.

**For this project (surface-based PFM / connectivity analyses) the session-separated approach is fine.**
If strict volumetric T1w compatibility were ever needed, the options are: (a) remove the T1w from ses-2 in BIDS so fmriprep falls back to ses-1 T1w for all sessions, or (b) re-run the full subject without `--session-label` using nipype workflow caching.
